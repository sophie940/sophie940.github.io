在红蛛用 Spring Boot 3.x + Drools 搭建论文格式审查系统，把审查规则沉淀成 .drl 文件、支持热更新，并设计了“正文引用 ↔ 参考文献”的双向映射闭环，解决单向正则比对漏判的问题。

正在做的论文 DocMut 把软件工程的故障注入方法搬到文档上；自己做的学霸机器是一个约 140KB 的单文件工具，双击就能在本地读几百页教材。

02作品

个人项目 · 可离线运行

学霸机器 · PDF 智能精读

给几百页的专业课教材做的精读工具：问一句，就定位到页码级的原文出处，而不是给一段无法核对的总结。

  • PDF.js 渲染 + 字符级索引，命中即定位原文出处
  • 扫描页自动降级 OCR，兜住没有文字层的教材
  • n-gram 候选排序 + LLM 二次确认匹配出处
  • 容错 JSON 解析与多级缓存，缓解 API 压力

取舍：先用 n-gram 把候选缩到可控范围，再让 LLM 二次确认——既不把整本书塞进上下文，也不让纯关键词匹配答不出出处。

边界：代码由 Claude Code 辅助生成；产品设计、链路集成与验收由我完成。

论文工作 · NAACL 2027 在投

DocMut · 文档缺陷注入基准

把 Defects4J / PIT 的故障注入方法从代码缺陷搬到文档缺陷，用来回答一个问题：现在的文档审查系统，是真的能查，还是只是被容易的测试集喂饱了。

  • 构建 50 篇真实感文档、144 条注入缺陷，覆盖格式 / 结构 / 引用 / 语义四类
  • 设计级联感知的单缺陷差分计数协议，修掉“同一缺陷级联触发多条告警被算成误报”的评测失真
  • 配套工具链：manifest 驱动缺陷注入、评测脚本与延迟 / 并发压测（混合引擎 5.1s/篇、纯 LLM 约 350s/篇，网关并发 1→100 成功率 100%）

取舍：只报受控基准的高召回没有意义，所以同时跑一套真人隐蔽缺陷，把“容易的测试集”带来的乐观偏差量化出来。

边界：基准与协议为论文共同成果；我负责基准设计、缺陷注入与评估主体工作。

多模态 AI 音乐情感伴侣
